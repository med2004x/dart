# Dart: 0 → Elite Systems / Backend Engineering

This repository is now organized as a dependency-ordered curriculum. The learner moves from fundamentals to computer architecture, mathematics, systems, backend engineering, distributed systems, performance, security, production, and open-source work.

## The route

| Step | Track | What you should be able to do afterward |
|---:|---|---|
| 00 | Orientation | Learn deliberately, debug, test, read code, and prove understanding |
| 01 | Go Core | Write idiomatic beginner/intermediate Go programs |
| 02 | Go Functions & Methods | Reason about functions, methods, receivers, and state |
| 03 | Go Worked Examples | Compare patterns against working reference code |
| 04 | C, Memory & Low-Level Programming | Understand memory, compilation, pointers, and undefined behavior |
| 05 | Problem Solving & Algorithms | Solve problems and reason about complexity |
| 06 | Linux & Developer Tools | Debug and inspect real Unix-like systems |
| 07 | Computer Architecture | Explain CPU, cache, memory, ISA, and storage behavior |
| 08 | University Mathematics | Handle analysis/calculus, probability, statistics, linear algebra, and discrete math |
| 09 | PostgreSQL Engineering | Build correct, performant database-backed systems |
| 10 | Operating Systems | Understand processes, memory, scheduling, filesystems, IPC, and synchronization |
| 11 | API Engineering | Design robust APIs and operational contracts |
| 12 | Networking | Understand protocols down to packets and sockets |
| 13 | Database Internals | Understand how a DBMS works beneath SQL |
| 14 | Distributed Systems | Build systems that survive partial failure |
| 15 | System Engineering | Design reliable production systems |
| 16 | Performance Engineering | Measure and optimize real bottlenecks |
| 17 | Security Engineering | Design and debug secure systems |
| 18 | Rust Systems | Use Rust for high-performance and low-level work |
| 19 | Production Engineering | Operate software safely in production |
| 20 | Open Source & Real Code | Contribute to unfamiliar mature codebases |
| 21 | Capstones | Integrate everything into substantial engineering projects |
| 22 | Business Communication | Write, present, and collaborate professionally |

see [`LIG-S1-MAP.md`](LIG-S1-MAP.md) — it maps each S1 subject to the track that covers it.

covered in more depth here than the course requires.

## How to read a lesson

Every lesson should answer five questions: what concept is being learned, what must be implemented or solved, what proves correctness, what failure should be deliberately observed, and what new problem transfers the idea.

## Mathematics requirement

The mathematics track is mandatory, not decorative. Complete the analysis/calculus, probability, statistics, linear algebra, and discrete mathematics sequences at university depth. The engineering applications at the end exist to connect the theory back to software systems.

## External material

## Existing solved/reference material

Existing implementation examples in the Go tracks are preserved. Treat them as references: first attempt the task, then inspect the solution, identify the difference, and reproduce the concept on a new problem.
